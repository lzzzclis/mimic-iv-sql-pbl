# 自测六题与SQL阅读指南

依据PPT第56页；自测是形成性评价，不计小组评分。以下为AI辅助的参考答案，小组应理解后自行作答。

1. **WHERE能否直接用本层SELECT刚起的别名？** 不能。WHERE筛原始行时，SELECT的新别名还未计算。筛分组用HAVING，或外套一个查询再用WHERE。PostgreSQL的ORDER BY可用输出别名，某些GROUP BY也可以，但不能由此推到WHERE。
2. **labevents怎样关联一次ICU入住？** 用subject_id/hadm_id对到该患者本次住院，再以charttime限定本次ICU或明确的研究时间窗。labevents没有stay_id；只用hadm_id会把同次住院的多次ICU血气混在一起。
3. **为什么Bipap mask匹配失败？** 记录可能有尾部空格，用btrim()先清洗；需要时再用ILIKE。查看真实值后再分类，而非猜字符串。
4. **NOT IN子查询出现NULL会怎样？** 可能使非匹配对象变为UNKNOWN并在WHERE里被丢弃；用相关NOT EXISTS表达“没有满足排除条件的记录”。不是把NULL直接等同0。
5. **结局用INNER JOIN会怎样？** 没有插管记录的达阈值者消失，分母缩小。应LEFT JOIN保留，并把缺少插管事件的结局标为FALSE；短随访另行汇报。
6. **为什么本地比例不必等于19%？** 数据2.2与原文起始人数不同，装置/FiO2同时规则、血气与监护配对、治疗限制字段、动脉标本确认、边界和缺失处理都有差别。应逐项解释，不能调参数凑19%。本次仅PF<80，不是原文17阈值、插补与回归的完整研究。

## 通俗阅读顺序

先把每层想成一张“名单”：原始ICU名单→成人非择期名单→装置与FiO2同时合格→排除已插管/气切/限制插管→每人保留首次合格入住→首次动脉PF<80→其中3h内插管。

- 一行病例表代表一次ICU入住；一行血气表代表一次血气。两表连接后的行数不再直接等于人数。
- t0像“加入观察名单”的时间；t_pf80像“第一次触发警报”的时间；t_imv像“真正发生插管”的时间。
- 结局率=触发警报后3h内插管的人数÷触发警报的人数。未插管的人仍是分母的一部分。
- `CREATE TEMP TABLE`只在当前连接创建临时草稿表；`JOIN`按编号拼信息；`WHERE`筛记录；`GROUP BY`合并；`DISTINCT ON`按排序只留首次；`FILTER`计数满足条件的人；`NULL`表示未记录。
- `LAG()`练习尚未标为掌握：它仅把上一条值放旁边，能帮助学习先后顺序；本次主分析不要求先有≥80再<80，因此不需要用LAG替换阈值定义。
